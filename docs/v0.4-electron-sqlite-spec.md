## 1. 版本目标

- `V040-G01`：Windows 桌面应用在关闭、重启、覆盖安装和异常退出后可靠恢复巡林官、身份与当前游戏状态。
- `V040-G02`：Electron 桌面版以主进程 SQLite 取代渲染进程 `localStorage`，同时保留 JSON 导入/导出。
- `V040-G03`：建立带模式版本、事务、修订号、备份、恢复和结构化错误的持久化边界。
- `V040-G04`：Windows 安装器允许用户选择安装位置；卸载器提供默认保留数据与显式彻底删除两种可理解、可验证的结果。

V0.4 的完成条件是本文验收项具有目标环境证据，不是“代码已经写完”或“开发构建可以运行”。

## 2. 范围与非目标

本版本交付 Windows Electron + SQLite、本地旧档一次性迁移、关键操作原子提交、JSON 备份交换、数据库备份/恢复、安全 IPC，以及可选择安装位置和卸载数据策略的安装包验收。

本版本不交付账号、云同步、服务器数据库、自动更新、静态数据加密、macOS/Linux 正式安装包，也不进行与持久化无关的大规模玩法或界面改版。

## 3. 数据事实来源

| 环境 | 事实来源 | 说明 |
|---|---|---|
| Electron 开发版与 Windows 安装版 | SQLite | V0.4 正式目标 |
| 浏览器 `npm run dev` | localStorage 兼容适配器 | 仅用于 Web 开发与现有回归测试 |
| JSON 文件 | 可移植交换格式 | 不是运行时事实来源 |

数据库固定由主进程放置在 `app.getPath('userData')/data/minerva-ranger.sqlite3`。渲染进程不能获得数据库句柄、SQL、任意 IPC 或文件系统路径能力。

## 4. 架构与运行时

```text
Vue / Pinia
  -> 同步内存工作副本 + 串行异步提交器
  -> sandbox preload 白名单 API
  -> ipcRenderer.invoke / ipcMain.handle
  -> PersistenceService 串行队列
  -> PersistenceDatabase
  -> node:sqlite / SQLite 文件
```

- Electron：`43.4.0`
- Electron Node：`24.18.1`
- SQLite：`3.53.1`
- 驱动：内置 `node:sqlite`，不引入 `better-sqlite3`
- BrowserWindow：`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`
- 页面：CSP、权限拒绝、导航限制、新窗口拒绝、IPC sender 校验

渲染层继续使用同步 Pinia 领域状态，但每次内存存储变更都会合并进一个串行 SQLite 快照提交。关键 UI 操作显式等待 `flushPersistence()`；失败时重新载入最后一次已提交快照，避免把乐观状态继续展示为成功。

## 5. 数据模型

- `schema_migrations`：数据库模式版本与校验和。
- `app_metadata`：全局数据修订号、默认身份初始化标记。
- `ranger_profile`：全局巡林官版本化 JSON 快照。
- `save_index`：身份顺序、选择和摘要。
- `identity_slots`：身份元数据、版本化 JSON 快照和修订号。
- `migration_log`：legacy 来源、指纹、状态、数量和错误。
- `backup_log`：备份原因、文件、模式、修订号和结果。

V0.4 采用“稳定元数据 + 版本化 JSON 快照”的混合方案。完整关系化查询不属于本版本。

## 6. 事务与状态规则

- `V040-T01`：持久化状态至少区分 `initializing`、`saving`、`ready`、`degraded`、`fatal`。
- `V040-T02`：桌面初始化失败时不回退到实际 localStorage 继续运行，也不覆盖旧数据。
- `V040-T03`：全局档案、身份索引和全部身份快照在一个 SQLite 事务中提交。
- `V040-T04`：每次提交携带期望修订号；陈旧写入以 `STALE_WRITE` 拒绝。
- `V040-T05`：身份创建/切换/重命名/删除/导入、地点解锁和收获显式等待提交；失败后重载数据库状态。
- `V040-T06`：普通深层变更由微任务合并并串行提交，不依赖 `beforeunload` 才保存关键结果。

## 7. legacy 迁移

1. preload API 初始化前，渲染层只读收集真实 localStorage 的索引、全局档案、身份主副本和初始化标记。
2. 主副本损坏时读取 backup；身份主副本和 backup 均损坏则停止迁移并报告，不静默跳过。
3. 主进程校验索引/身份一一对应、对象结构、ID 和大小限制，计算来源指纹。
4. 全部 legacy 数据和 `migration_log` 在一个事务中写入；失败全部回滚。
5. 成功后 SQLite 成为桌面事实来源，localStorage 被保留且不再作为桌面工作存储。
6. 数据库非空或来源已处理时不重复迁移；失败记录允许修复后重试。

## 8. 备份、恢复与错误

- JSON 导入前自动执行 SQLite 在线备份；备份失败时不继续导入。
- 手动备份和数据库恢复可从应用内发起。
- 恢复前关闭数据库并把当前文件改名保留；恢复失败时重新放回原文件。
- 备份候选必须通过 `integrity_check`，过新模式不能恢复。
- 损坏、只读/不可写、模式过新、陈旧写入、非法载荷和不可信 IPC 均使用结构化错误码。
- `degraded` 状态允许重试或恢复；`fatal` 状态禁止进入正常游戏写入。

## 9. Windows 安装与卸载规则

- `V040-I01`：交互式安装使用引导式安装器，允许选择安装范围和安装目录；静默安装仍支持显式 `/D=目标目录`。
- `V040-I02`：覆盖安装和自动更新路径复用既有安装目录，不再次询问目录，也不得删除用户数据。
- `V040-I03`：交互式卸载以两个互斥单选项明确提供“仅删除应用”和“删除应用及全部本地数据”两种结果，默认仅删除应用并保留数据。
- `V040-I04`：选择彻底删除后必须二次确认，默认按钮为“否”；取消确认时返回并恢复到“仅删除应用”的安全默认项。
- `V040-I05`：彻底删除只清理应用自己的 `%APPDATA%/minerva-ranger` 数据、SQLite、内部备份与设置，不删除用户导出到其他目录的 JSON 文件。
- `V040-I06`：静默卸载默认保留数据；只有传入显式删除数据参数时才允许清理。更新触发的旧版本卸载永远按保留数据处理。

用户所说的“下载路径”在 Windows 安装包语境中定义为“程序安装路径”。安装包文件下载到哪个目录由浏览器或下载工具管理，不属于应用安装器控制范围。

## 10. 验收条件

- `V040-AC01`：全新安装创建 SQLite，写入并重启后数据一致。
- `V040-AC02`：现有全局档案和全部身份从 localStorage 恰好迁移一次，数量与内容一致。
- `V040-AC03`：重复启动、迁移失败后重试和覆盖安装不重复、不丢失数据。
- `V040-AC04`：关键多对象写入要么全部提交，要么全部回滚；陈旧/非法写入不改变数据库。
- `V040-AC05`：JSON 往返等价；非法导入和备份失败保持原数据不变。
- `V040-AC06`：损坏、只读/写入失败和过新模式不会静默覆盖，用户有重试/备份恢复入口。
- `V040-AC07`：渲染层不能访问 Node、SQLite 或任意 IPC，导航、窗口、权限和 CSP 受限。
- `V040-AC08`：单元、迁移、事务、渲染适配和现有玩法回归全部通过。
- `V040-AC09`：生产构建、Electron 双启动、win-unpacked、NSIS 引导式安装/覆盖安装/卸载通过，静默与默认交互卸载保留用户数据。
- `V040-AC09A`：交互式安装可选择安装目录；静默 `/D=` 安装在隔离目录生成可启动程序，覆盖安装沿用目录且不丢失数据。
- `V040-AC09B`：交互式卸载显示两个互斥单选项并默认保留数据；显式选择并确认“删除应用及全部本地数据”后清理应用数据，外部导出文件不受影响；更新卸载不进入删除路径。
- `V040-AC10`：版本号、README、CHANGELOG、开发进度和 Notion 证据一致；全部目标环境验收后才能进入“待发布”。

## 11. 发布前仍需人工确认

- 用真实的 V0.3/localStorage 用户目录执行一次迁移，人工核对全局档案、身份数量、笔记、地图和当前任务。
- 在打包应用中实际操作一次备份列表与恢复界面，并确认失败提示可理解。
- 用保留的旧版安装包执行真实跨版本覆盖升级；当前自动化已验证同版本覆盖安装和同用户目录重启。
- 在交互式安装器中实际选择一次非默认目录；核对两个卸载单选项的默认值和互斥状态，并分别人工执行一次默认保留数据卸载和显式彻底删除卸载，核对二次确认文案与结果。
- 发布前决定是否保留当前未签名安装包；代码签名不在 V0.4 功能实现范围内，但会影响 Windows 下载信誉提示。
