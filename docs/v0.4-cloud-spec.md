# V0.4 Cloud 网络版规格

> 规格状态：Revision 1，首个可部署版本开发中
>
> 日期：2026-08-16
>
> 实现分支：`cloud`
>
> 版本约定：`V0.4` 表示产品功能阶段；`Desktop` 与 `Cloud` 表示运行载体；`local`、`development` 与 `production` 表示部署环境，不单独递增产品版本号。

## 1. 问题、目标与成功标准

- `V040-C-G01`：让 1～10 位受邀请用户通过 Windows 或 macOS 的现代桌面浏览器使用同一套应用，无需下载、签名或公证安装包。
- `V040-C-G02`：每位登录用户拥有相互隔离的云端巡林官与身份存档，并能在不同电脑间继续使用。
- `V040-C-G03`：复用 V0.4 已验证的 Vue、Pinia、存档领域模型和 JSON 导入/导出，不分叉玩法实现。
- `V040-C-G04`：在并发窗口、断网、身份验证失败和超限数据场景中不静默覆盖云端数据。
- `V040-C-G05`：以 Cloudflare Workers、Static Assets、Access 和 D1 建立可在低使用量下运行、可观察、可迁移的首个网络版本。

成功标准是受邀请用户能在两种桌面系统的浏览器中登录、创建或修改身份、刷新或换电脑后恢复相同数据；未受邀请者无法读取 API；冲突与失败具有明确反馈和恢复入口。

## 2. 范围、非目标与约束

本版本交付桌面浏览器 Web 应用、Cloudflare Access 登录、同源 Worker API、D1 用户隔离快照、修订号写入、同步状态、JSON 手工备份、本地开发数据库、自动化测试和预览部署准备。

本版本不交付：

- Electron 本地 SQLite 与云端的双向同步；桌面版继续独立运行。
- 多人共同编辑同一份存档、实时协作、组织/团队空间或管理员后台。
- 离线写入队列、跨标签自动合并、Service Worker 或完整 PWA 安装体验。
- 手机和平板专用交互、原生应用商店发布、支付或公开注册。
- 对现有玩法、视觉体系或存档结构进行无关重写。

约束：首期 1～10 位受邀请用户；在线优先；单用户云端快照最多 1,500,000 UTF-8 字节；最多 1000 个身份；远程环境必须使用 Access 验证，开发身份只能在 `localhost`、`127.0.0.1` 或 `[::1]` 使用。

## 3. 参与者与核心流程

### 3.1 参与者

- `V040-C-A01` 受邀请用户：通过 Access 一次性验证码或已配置身份提供商登录，读取和写入自己的快照。
- `V040-C-A02` 发布管理员：创建 D1、Worker、Access 应用和允许名单，执行迁移与部署，查看结构化日志。
- `V040-C-A03` Cloudflare：提供边缘静态资源、Worker 运行时、Access JWT 与 D1。

### 3.2 首次进入

1. 用户访问应用域名并通过 Access。
2. Worker 验证 `Cf-Access-Jwt-Assertion` 的签名、签发方和应用 audience，以 `sub` 作为稳定用户主键。
3. API 查询该用户的快照；不存在时返回修订号 `0` 和空快照。
4. 前端在内存存储中按现有规则创建默认身份，再以期望修订号 `0` 写入云端。
5. 成功后界面显示“云端已同步”和当前修订号。

### 3.3 日常写入

1. 领域 Store 继续同步写入内存存储。
2. 普通连续修改在 1.2 秒内合并；关键身份操作继续显式等待 `flushPersistence()`。
3. 前端使用 `If-Match` 发送期望修订号，并使用 `Idempotency-Key` 保护网络重试。
4. D1 在单条条件写入中递增修订号；只有当前修订与期望值一致时提交。
5. 返回新修订后状态变为“云端已同步”。

### 3.4 冲突恢复

当 D1 当前修订与页面期望修订不一致时，API 返回 `409 STALE_REVISION`，且不改变数据库。页面进入“版本冲突”，停止自动覆盖；用户可导出当前身份，或确认“载入云端最新版本”并放弃当前页面尚未同步的修改。

## 4. 功能、状态与业务规则

- `V040-C-S01`：事实来源是 D1 中以 Access `sub` 为主键的一条版本化 JSON 快照；email 只用于显示与审计，不作为主键。
- `V040-C-S02`：前端不得持久化 Access JWT，也不得从 email、请求参数或客户端指定字段选择其他用户数据。
- `V040-C-S03`：远程写入必须同时通过 Access JWT、同源 `Origin`/`Sec-Fetch-Site`、合法修订号、幂等键、结构与大小校验。
- `V040-C-S04`：状态至少区分 `initializing`、`pending`、`saving`、`ready`、`offline`、`conflict`、`degraded` 和 `fatal`。
- `V040-C-S05`：云端初始化失败时不得回退到 localStorage 创建另一份看似成功的存档。
- `V040-C-S06`：网络失败保留当前页面内存中的修改并显示“离线未同步”；关闭页面前不承诺离线修改可恢复。
- `V040-C-S07`：JSON 导入/导出继续作为用户可控制的可移植备份；它不是运行时事实来源。
- `V040-C-S08`：API 响应使用 `Cache-Control: no-store` 和结构化错误；日志只记录请求 ID、路由、状态、时延与用户主键短哈希，不记录 JWT、email 或快照正文。

## 5. 数据与接口契约

### 5.1 D1 表

- `cloud_users(subject, email, created_at, last_seen_at)`：Access 主体和最近访问时间。
- `cloud_snapshots(subject, revision, schema_version, payload_json, payload_bytes, last_request_id, created_at, updated_at)`：每位用户的一条完整快照。
- Wrangler 的 `d1_migrations`：记录已执行迁移。

### 5.2 API

| 接口                | 行为                               | 成功结果                                                 |
| ------------------- | ---------------------------------- | -------------------------------------------------------- |
| `GET /api/health`   | 最小健康检查，不返回绑定或用户数据 | `{ ok, environment }`                                    |
| `GET /api/session`  | 返回经过验证的显示身份和环境       | `{ user, environment }`                                  |
| `GET /api/snapshot` | 读取当前 Access 主体快照           | `{ revision, schemaVersion, snapshot, updatedAt, user }` |
| `PUT /api/snapshot` | 条件写入当前主体快照               | `{ revision, updatedAt, idempotent }`                    |

API 错误统一为 `{ error: { code, message, recoverable, requestId, details? } }`。预期错误至少包括 `AUTH_REQUIRED`、`AUTH_INVALID`、`ORIGIN_REJECTED`、`REVISION_REQUIRED`、`STALE_REVISION`、`INVALID_PAYLOAD`、`PAYLOAD_TOO_LARGE` 和 `INTERNAL_ERROR`。

## 6. 外部依赖与部署契约

- Cloudflare Worker 使用当前兼容日期、`nodejs_compat`、Static Assets SPA fallback、`/api/*` Worker-first 路由、智能放置和可观察性。
- 预览与正式环境各自使用独立 D1；绑定名称固定为 `DB`。
- 远程环境变量：`ENVIRONMENT`、`AUTH_MODE=access`、`MAX_SNAPSHOT_BYTES=1500000`、`TEAM_DOMAIN`、`POLICY_AUD`。
- Access 应用保护完整应用域名，策略仅允许管理员明确邀请的 email；Worker 仍独立验证 Access JWT。
- 发布顺序固定为：创建 D1 → 写入真实 ID → 远程执行迁移 → 部署 Worker/Assets → 创建或绑定 Access 应用 → 填写 team domain/audience → 再部署 → 验证未登录、已登录、写入与跨设备恢复。

## 7. 异常、恢复与边界

- D1 不可用或 Worker 异常：返回请求 ID，前端保持未同步状态，允许稍后重试。
- Access 配置缺失：远程环境以不可恢复配置错误停止，不允许开发身份兜底。
- 同一页面重复请求：相同幂等键返回原修订，不重复递增。
- 两个页面同时写入：只有一个修订成功；另一个得到冲突且数据不变。
- D1 中快照 JSON 损坏：返回 `SNAPSHOT_CORRUPTED`，不启动空存档覆盖。
- 超过 1.5 MB：拒绝写入，原修订保持不变；用户可导出 JSON 后清理数据。
- 非桌面小视口：本版本不声明专用支持，但不得破坏现代桌面浏览器的最小工作区。

## 8. 验收条件

- `V040-C-AC01`：桌面构建、Cloud 构建和 V0.4 的 53 项回归测试全部通过。
- `V040-C-AC02`：真实 Workers Vitest + D1 覆盖首次读写、读取恢复、用户隔离、幂等重试、陈旧修订、同源拒绝和大小限制。
- `V040-C-AC03`：本地 Wrangler 能应用迁移，并能在本地 Cloud 模式完成登录替身、创建身份、刷新恢复和同步状态显示。
- `V040-C-AC04`：未登录访问远程域名被 Access 拦截；受邀请账号能进入；未邀请账号被拒绝。
- `V040-C-AC05`：Windows 与 macOS 的当前主流桌面浏览器能完成登录、创建/修改、刷新恢复、JSON 导出和退出再登录。
- `V040-C-AC06`：两个浏览器窗口制造陈旧修订时，后写窗口显示冲突，数据库保留先提交版本，用户可明确载入云端版本。
- `V040-C-AC07`：远程日志不出现 JWT、email 或快照正文，错误响应包含可定位请求 ID。
- `V040-C-AC08`：部署文档记录真实 Worker、D1、Access 应用、域名、迁移和回滚步骤；所有目标环境证据完成后才标记可邀请试用。

## 9. 环境绑定状态

预览环境已从用户的 Cloudflare 账号取得并记录非秘密资源引用：D1 `database_id`、`workers.dev` 地址、Zero Trust team domain、Access application audience、OTP 身份提供商和 owner 允许策略。具体值与部署版本见 `docs/cloud-development-progress.md`。

正式环境尚未创建；新增 1～10 位试用用户时，仅扩展 Access 允许策略，不把账号、JWT、OTP、API token 或其他秘密提交到代码库。
